# Движок, редактор и локальная игра

Репозиторий содержит движок, редактор, шейдеры, инструменты импорта и проверки.
Игровой контент пока остаётся на прежних локальных путях, но исключён из Git:

- `assets/` — сцены, модели, материалы, текстуры и импортированные пакеты игры;
- `art/` — исходники Blender, экспорты и промежуточные файлы;
- `scripts/blender/*freight*.py`, `scripts/import_freight_yard.ps1`,
  `scripts/package_freight_yard.py`, `scripts/run_freight_yard.cmd` — инструменты демо;
- `docs/FREIGHT_YARD.md` — описание и результаты конкретной демо-игры.

Исключения внутри `assets/`, которые остаются в репозитории:

- `sky_clouds.png` — обязательный ресурс встроенного неба рендера;
- `smaa/` — таблицы алгоритма сглаживания;
- `validation/` — минимальные технические fixtures для проверок движка.

Новый игровой пакет внутри `assets/` игнорируется автоматически. Новые скрипты
или документы игры размещайте внутри `art/` либо добавляйте точечное правило
в `.gitignore`; общие инструменты движка остаются версионируемыми.

Runtime и editor читают локальный `assets/scenes/editor_scene.json`. Если файла
нет, используется встроенная техническая сцена с примитивами, без создания
файлов на диске. Save редактора сохраняет сцену в этот игнорируемый путь.
Ошибки чтения и повреждённые документы не скрываются резервной сценой.

Игровая логика реализована общей runtime-сессией. В редакторе кнопка Play (или
`F5`) временно добавляет runtime-персонажа и включает камеру от третьего лица;
Pause замораживает симуляцию, а Stop восстанавливает authored-сцену и прежнюю
редакторскую камеру. `WASD` задаёт движение и разворот, `Shift` переключает
ходьбу на бег, `Space` выполняет прыжок, а мышь вращает камеру. Play автоматически
захватывает мышь и скрывает курсор. `Esc` возвращает курсор без остановки игры,
`ЛКМ` по вьюпорту снова включает игровое управление. Обычный запуск собранного
`vulkan_cube` запускает ту же игровую сессию
сразу и использует захваченную мышь для вращения камеры.

Персонаж использует высоту authored ground plane (либо нулевую плоскость, если
ground отсутствует); столкновения с произвольной геометрией и terrain пока не
реализованы. Benchmark, render fixtures и stress scene сохраняют прежнюю
fly-camera, поэтому их управление и измерения не меняются.

Сборка по-прежнему копирует доступный локальный `assets/` рядом с executable.
Так сохраняется запуск существующей демо-игры; чистый checkout собирается и
запускается со служебными ресурсами. Git ignore не исключает файлы из локальной
упаковки. Каталог `bin/assets` существующей сборки может содержать старые копии.

Streaming validation по умолчанию использует fixture из `assets/validation`;
для модели игры передайте `-StreamAsset` относительно `assets/`. Benchmark suite
`Lod` требует явного `-ModelAsset` относительно `assets/`. Сравнивайте результаты
только на одинаковом ассете: прежние измерения с моделью пня не сопоставимы с
техническим fixture.

Уже отслеживаемые игровые файлы убраны из индекса через `git rm --cached` и
сохранены локально. Это подготавливает удаление из следующего коммита, но не
переписывает историю: в старых коммитах файлы остаются. Отдельный репозиторий
игры и выбор внешнего project root — следующий этап разделения.
