# GT7 tone mapping: SDR / ICtCp

`shaders/gt7_tone_mapping.glsl` переносит SDR-ветку официального
[GT7 reference v1.0 от Polyphony Digital, 2025-08-10](https://blog.selfshadow.com/publications/s2025-shading-course/pdi/supplemental/gt7_tone_mapping.cpp).
Сохранены GT7 curve с convergent shoulder, смешивание per-channel результата
с ICtCp chroma и затухание chroma в highlights. Это не сокращённая GT Sport /
Uchimura curve. Лицензия MIT сохранена в `LICENSES/gt7_tone_mapping.txt`.

SHA-256 полученного reference:
`94DF7E7E310B9423EBB5AAAA29416F376EBBAE66E0948FB259F8688314B29822`.

## Контракт и параметры

`vec3 gt7ToneMapping(vec3 linearRec709)` принимает HDR radiance в линейном
Rec.709 с exposure = 1 и возвращает линейный Rec.709 в диапазоне `[0, 1]`.
Следующий sRGB attachment выполняет единственное transfer-function encoding.
Не подавать на вход sRGB-кодированные значения и не применять OETF внутри shader.

| Параметр reference | Значение |
|---|---:|
| UCS | ICtCp, default reference |
| Reference luminance: framebuffer 1.0 | 100 cd/m² |
| SDR paper white | 250 cd/m² |
| `framebufferLuminanceTarget` / peak | 2.5 |
| SDR correction factor | 0.4 |
| Alpha | 0.25 |
| Gray point | 0.538 |
| Linear section | 0.444 |
| Toe strength | 1.280 |
| Blend ratio | 0.6 |
| Chroma fade start / end | 0.98 / 1.16 |

При таких настройках нейтральное HDR `1.0` даёт примерно `0.4`, а `0.18` —
`0.05795` линейного SDR. Это ожидаемое поведение официальной SDR-калибровки,
а не компенсация, подобранная под Reinhard. При одинаковом exposure изображения
двух операторов будут различаться по яркости. Значение 250 nits здесь является
моделью reference, а не измеренной яркостью подключённого монитора.

Constant folding фиксированных параметров даёт:

```text
k       =  0.7413333333333334
kA      =  2.9633333333333334
kB      = -3.3733512380644313
kC      = -0.5395683453237410
I(2.5)  =  0.6025591549907509
```

Параметры и constants вычислены без подгонки. FP32 shader может немного
отличаться от исходного C++ из-за порядка операций, constant folding, FMA и
реализации `pow` / `log2` / `exp2`.

## Преобразования цвета и защищённая граница

GT7 reference принимает Rec.2020. Поэтому перед ним выполняется линейная
Rec.709 → Rec.2020 матрица, после него обратная. Матрицы рассчитаны из primaries
[BT.709](https://www.itu.int/rec/R-REC-BT.709/en) и
[BT.2020](https://www.itu.int/rec/r-rec-bt.2020-2-201510-i/en) с общим D65
`(x = 0.3127, y = 0.3290)`; направление преобразования также описано в
[BT.2087-0](https://www.itu.int/dms_pubrec/itu-r/rec/bt/R-REC-BT.2087-0-201510-I%21%21PDF-E.pdf).
Они работают с линейными значениями, без chromatic adaptation и без gamma.
В GLSL записаны `dot` по строкам, чтобы исключить неоднозначность column-major
конструктора `mat3`.

```text
Rec.709 → Rec.2020:
 0.627403896   0.329283038   0.043313066
 0.069097289   0.919540395   0.011362316
 0.016391439   0.088013308   0.895595253

Rec.2020 → Rec.709:
 1.660491002  -0.587641139  -0.072849863
-0.124550475   1.132899897  -0.008349423
-0.018150763  -0.100578898   1.118729661
```

Отличия на границе движка, отсутствующей в reference:

- Отрицательные входные компоненты, в том числе reconstruction undershoot,
  ограничиваются нулём до PQ; NaN-компоненты заменяются нулём.
- Вход ограничен сверху `1e20`, включая положительную бесконечность. Это
  предотвращает FP32 overflow в промежуточных операциях и находится далеко за
  пределами конечных значений используемого RGBA16F target (`65504`).
- Результат после обратного преобразования ограничивается Rec.709 `[0, 1]`.
  Насыщенные цвета могут выйти за меньший gamut; здесь используется явный clip,
  без отдельного perceptual gamut mapper. Chroma processing внутри GT7 сохранён.

Небольшая разница компонентов нейтрального серого у reference связана с его
округлёнными обратными ICtCp/LMS коэффициентами. Они сохранены, а не заменены
другими коэффициентами ради более красивых чисел.

## Проверки интеграции

Перед включением пути нужны shader compile + `spirv-val`, Windows GPU readback
этих эталонов, проверка AA off / SMAA / FSR при одинаковой HDR-сцене и exposure,
и отдельное сравнение GPU display-pass timings с Reinhard. GT7 использует PQ,
два RGB → ICtCp преобразования и одно обратное; уменьшение стоимости относительно
нынешнего Reinhard не предполагается. Выбор оператора должен оставаться явным.
