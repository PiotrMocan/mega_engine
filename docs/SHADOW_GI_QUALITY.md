# Стабильность теней и стоимость GI

Исходная версия: `ab6f01a`. Windows x64, RX 6800. Пользователь наблюдает
плавающие края и просветы при динамическом освещении как с GI, так и без GI,
в том числе при остановленных камере и времени.

## План текущей итерации

1. Воспроизвести статичный режим с GI off/voxel и Off/SMAA/FSR; сохранить
   исходную сборку и изображения. Проверить Pause в редакторе.
2. Исправить остановку часов, стабильность проекции и перекрытие каскадов,
   фильтрацию и bias. Проверять тонкие препятствия, границы каскадов,
   движение камеры и солнца.
3. Снять доступный аппаратный GPU profile. Удешевить выборку GI отдельным
   проходом меньшего разрешения с восстановлением по depth/normal; измерять
   стоимость всех добавленных ресурсов и проходов вместе.
4. Добавить консервативное отсечение shadow casters с отдельным LOD и
   сохранением простого пути для маленькой сцены.
5. Windows Debug/Release/ASan, CPU tests, shader compile/spirv-val, sync
   validation, повторные запуски/resize, контролируемый A/B benchmark.

## Первичная диагностика

- `EditorApplication` учитывает Pause только при обновлении камеры.
  `Renderer::prepare_lighting` продолжает увеличивать час суток.
- Солнце для CSM округляется до 15 игровых секунд (около десяти обновлений
  в секунду при стандартной длительности суток). Это создаёт ступенчатое
  движение даже при плавном прямом освещении.
- Радиус каскада вычисляется по world-space corners и округляется, что
  связывает его погрешность с позой камеры. Blend начинается до near plane
  следующего каскада, но отдельного гарантированного overlap нет.
- Receiver bias задан в нормализованной глубине одинаково для каскадов;
  в модельном шейдере он зависит от normal map. Фильтр — один hardware PCF.
- В исходной canonical scene при `--day-cycle off` выборки статичных кадров
  Off/SMAA совпадают с GI и без него. В FSR обнаружены небольшие изменения
  пикселей. Это не подтверждает воспроизведение всех артефактов пользователя.

Captures и runtime baseline: `build/windows-release/lighting-quality-20260912`.
Исходная диагностика: `scripts/shadow_validation_windows.ps1`.

## Внесённые исправления

- Pause в Play останавливает общий lighting clock независимо от состояния GI.
  Resume не меняет Advance time; явно выключенный цикл остаётся выключенным.
- Масштаб каскада вычисляется в пространстве камеры, light basis — относительно
  начала координат. Перевод центра в light space и привязка к texel grid не
  меняют масштаб проекции при повороте/перемещении камеры.
- Следующий каскад покрывает 10% overlap до предыдущего split. Дополнительный
  запас сохраняет весь footprint фильтра внутри atlas tile.
- Receiver bias выражен через world-space размер texel и масштаб глубины
  каждого каскада. Для моделей используется геометрическая нормаль;
  normal map продолжает участвовать в BRDF.
- Солнце для shadow atlas квантуется до одной игровой секунды вместо 15.
  Неизменные камера/свет/геометрия сохраняют кеширование atlas.
- Вместо одной comparison выборки используется tent PCF [1,2,1]. Его
  сепарабельные веса объединены в четыре hardware comparison выборки.
  Покадровых случайных смещений и накопления истории в фильтре нет.
  Явный LOD 0 устраняет зависимость выборки от неявных производных внутри
  ветвлений выбора каскада и blend-полосы.
- Ambient/приближённые отражения неба больше не добавляют диск солнца вторично
  поверх прямого BRDF, обходя shadow visibility. В видимом небе диск сохранён.

Размер Lighting UBO вырос с 448 до 464 байт; новое поле вычисляется только
при изменении матриц. GPU-ресурсы, очереди и схема frame ownership не менялись.
Нет новых allocations, readback, queue waits или per-frame Vulkan objects.

## Проверка качества

- CPU tests: Pause/Resume/Advance time для GI off и voxel; frustum coverage
  с запасом на PCF, включая вертикальный свет и aspect 0.5/1.778/4;
  100 положений и направлений камеры с неизменным масштабом и целочисленным
  смещением shadow texels.
- В canonical scene и закрытой комнате по шесть последовательных кадров
  для GI off/voxel × Off/SMAA/FSR. На сетке 4×4 без HUD кадры Off/SMAA
  совпадают. FSR проверяется как temporal-метод: отличия записываются,
  нулевое расхождение от него не требуется.
- Сравнение фильтров на RX 6800: 51840 выборок canonical кадра, GI off,
  Off; четыре выборки против девяти дают максимум 1/255, среднее 0.00122/255.
  Это сравнение конкретного hardware PCF, а не гарантия побитового равенства
  на всех драйверах: Vulkan допускает зависимую от реализации фильтрацию
  depth comparison.
- Закрытая комната: день/ночь/рассвет, реальное удаление/восстановление крыши,
  перенос GI volume, переключение GI, AA и present mode, resize. После
  восстановления крыши возвращается исходное изображение.

Исходное сильное плавание при явно выключенном Advance time пока не
воспроизведено на контрольных сценах. Исправлены подтверждённые ошибки кода;
это не доказательство устранения каждого проявления на сцене пользователя.
Субпиксельные изменения FSR и ограничения coarse voxel GI остаются.

## GPU profile

Нативный Radeon Developer Panel CLI из RDTS 2026-05-28 записал
`before-off.rgp` и `before-voxel.rgp` с instruction tracing и hardware counters.
Файлы находятся рядом с baseline runtime. Clocks восстановлены инструментом
после capture. Это отдельные диагностические запуски; их FPS не используется
для A/B. Захват трассы не заменяет анализ occupancy/ISA конкретного draw.

Дополнительно записан `four-tap-voxel.rgp`. Code objects обеих GI-трасс
извлечены из RDF и проверены нативным Radeon GPU Analyzer. У скомпилированных
fragment shaders нет VGPR/SGPR spills; основные варианты геометрии используют
64 VGPR до правки и 61–63 после первого варианта tent PCF. Увеличения register
pressure, объясняющего замедление, здесь не обнаружено. В ISA двухкаскадной
ветки стало восемь comparison fetches вместо двух (четыре вместо одной
на каскад); legacy-ветка сохраняет ещё одну выборку. Финальная правка также
переносит произведение texel size × depth scale из fragment shader в C++.

Raw/derived SPM chunks присутствуют в трассах. Агрегаты всего capture
не выдаются за аппаратные показатели конкретного draw или доказательство
bottleneck. Полный анализ wave occupancy и instruction timing через RGP UI
в этой сессии не выполнен.

## Windows gates

- Финальная сборка: Debug, Release и MSVC ASan; в каждой прошли все шесть
  наборов CTest. Шейдеры пересобраны и прошли `spirv-val` для Vulkan 1.3 /
  SPIR-V 1.5; runtime SPIR-V обновлён вместе с GLSL.
- Debug/ASan: проверены комната, переключение света/GI/AA, resize,
  present mode, startup/shutdown и сцена из 100000 движущихся экземпляров.
  Synchronization validation не сообщает ошибок, при shutdown —
  `Live GPU allocations: 0 (0 bytes)`.
- Нативные clang-tidy и MSVC `/analyze` + Core Check выполнены для
  `lighting.cpp`, `renderer_lighting.cpp`, `editor_application.cpp`;
  изменённые файлы проверены повторно после уточнений. Новых подтверждённых
  lifetime/bounds/overflow ошибок не обнаружено. Общие style/Core Guidelines
  warnings на C API, индексах фиксированных массивов и GLM остаются;
  это не отчёт о нуле предупреждений во всём проекте.
- Связь кнопки Pause с clock проверена по коду и CPU regression test.
  Автоматического нажатия Pause в UI редактора не было: его executable
  не предоставляет MCP, тесты запускают общий renderer через `vulkan_cube`.
- `build/` содержит только три разрешённых Windows tree. `git diff --check`
  проходит. Commit/push не выполнялись.

Последние логи: `lighting-quality-20260912/build-*-compact.log`,
`shaders-compact.log` внутри Windows Release tree;
`shadow-compact*.log` внутри Debug/ASan tree. Промежуточные серии с 9 и 4
выборками сохранены отдельно; их результаты нельзя смешивать с финальным A/B.

## Финальный A/B, 2026-09-12

Baseline `ab6f01a` с сохранёнными exe/SPIR-V/assets; сравнение с текущей
правкой (464-byte UBO, четыре PCF выборки). RX 6800, Ryzen 7 9700X,
Windows x64, драйвер 32.0.21045.5002, Release, 1920×1080, IMMEDIATE,
AA off, динамические сутки длиной 600 секунд. Для stress — 100000
экземпляров, движущиеся камера и стена. По три чередующихся прогона каждой
стороны; прогрев 5 секунд, измерение 15 секунд. Clocks/температура не
фиксировались; power scheme и фоновые процессы записаны в environment JSON.

В таблице — медианы независимых прогонов, до → после:

| Сцена / GI | FPS | Изменение FPS | 1% low | CPU frame, ms | GPU frame, ms |
| --- | --- | --- | --- | --- | --- |
| Canonical / off | 2631 → 2558 | −2.8% | 1811 → 1784 | 0.380 → 0.391 | 0.203 → 0.216 |
| Canonical / voxel | 839 → 785 | −6.5% | 739 → 690 | 1.192 → 1.274 | 0.997 → 1.081 |
| 100k / off | 986 → 970 | −1.7% | 835 → 818 | 1.014 → 1.031 | 0.825 → 0.839 |
| 100k / voxel | 665 → 645 | −3.0% | 523 → 508 | 1.504 → 1.550 | 1.302 → 1.350 |

Разброс FPS по трём прогонам:

| Сцена / GI | До, min–max | После, min–max |
| --- | --- | --- |
| Canonical / off | 2610–2668 | 2554–2569 |
| Canonical / voxel | 838–839 | 781–786 |
| 100k / off | 981–988 | 965–970 |
| 100k / voxel | 665–668 | 642–645 |

Регрессия с GI выше 3% исследована и оставлена как измеренный компромисс
качества этой правки. В canonical GI geometry pass вырос с 0.962 до 1.035 ms;
средняя стоимость shadow pass — с 0.00083 до 0.01299 ms. Atlas при движении
солнца обновляется примерно 144 раза/сек вместо 9.6 при стандартной скорости
суток. Фильтрация теперь выполняет четыре сравнения на каскад вместо одного.
Это не бесплатная оптимизация: дополнительная GPU стоимость — около 0.084 ms.

На 100k камера уже движется каждый кадр, поэтому частота atlas не растёт:
shadow pass остался около 0.569 ms. Дополнительные 0.048 ms режима GI
почти целиком приходятся на geometry pass (0.654 → 0.701 ms). Voxel geometry /
radiance остаются около 0.015 / 0.0017 ms в среднем по кадрам. Во время
статичной canonical сцены повторной voxelization нет.

Для canonical GI CPU command record: 0.0290 → 0.0310 ms, submit:
0.0274 → 0.0279 ms, present: 1.059 → 1.136 ms; основной прирост frame time
следует за GPU. Fence wait: 0.0174 → 0.0179 ms. В stress GI CPU scene
preparation: 0.0505 → 0.0556 ms;
эта серия не доказывает оптимизацию CPU. Полные CPU/GPU стадии сохранены
в JSON, а не заменены одним FPS.

Промежуточный фильтр из девяти выборок дал около 1.1045 ms GPU и 768 FPS
для canonical GI. Сокращение до четырёх сохранило его внешний вид в проверенном
кадре и снизило GPU frame примерно до 1.081 ms. Перенос произведения bias
в C++ уменьшил UBO и повторную арифметику; отдельного значимого ускорения
в этой серии не показал. Legacy в отдельной тройной серии изменился на −1.2%,
в пределах локального разброса; эта серия предшествует сокращению UBO.

Артефакты финального сравнения внутри `build/windows-release`:
`shadow-compact-comparison-20260912`, `shadow-compact-stress-20260912`,
`lighting-quality-20260912/final-summary.json`.

## Следующие этапы исходного плана

Отдельный проход GI меньшего разрешения, bilateral reconstruction,
компактизация shadow casters и shadow LOD в эту правку общего пути теней
не включены. Для них нужны отдельные изменения ресурсов/проходов и проверки
на disocclusion, тонких препятствиях и разрушении мира. Текущие исправления
не дают гарантии сохранения FPS при добавлении этих технологий.
