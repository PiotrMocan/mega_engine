# Разрешение теней

В панели Renderer настройка **Shadow resolution** переключает размер карты во
время работы. Через CLI: `scripts\run_windows.cmd --shadow-resolution 4096`.
Работает с динамическими сутками, с GI и без GI, а также с legacy-освещением.

| Вся карта | Каждый из 4 каскадов | D32, данные глубины без служебных накладных расходов |
| --- | --- | --- |
| 1024×1024 | 512×512 | 4 MiB |
| 2048×2048 (по умолчанию) | 1024×1024 | 16 MiB |
| 4096×4096 | 2048×2048 | 64 MiB |
| 8192×8192 | 4096×4096 | 256 MiB |

Legacy использует всю карту для одной проекции. Размер не меняет дальность
теней или разрешение voxel GI. Увеличение повышает детализацию теней, требует
больше памяти и работы GPU. Настройка действует в текущем сеансе; для следующего
запуска её можно передать через CLI. Неподдерживаемые GPU размеры недоступны в UI
и отклоняются через API/CLI.

Выполненные изменения:

- Добавлен единый набор размеров, проверка CLI, UI, MCP и поле benchmark JSON.
- Карта пересоздаётся на границе кадра после fence всех использовавших её
  submissions. Обновляются оба набора descriptors каждого frame, сохраняются
  формат и pipelines. Сбрасываются кеш каскадов и temporal history.
- Расширены проверки покрытия и texel snapping каскадов на все размеры;
  добавлены runtime-переключения с validation и A/B для 2048.

В обычном кадре добавлено только сравнение текущего и запрошенного размеров.
При переключении возможна разовая пауза на завершение кадров и создание карты.
Новая карта создаётся до уничтожения старой; пиковая память включает обе.
`vkDeviceWaitIdle`, пересоздание pipelines и перераспределение descriptor sets
для этого не используются. Матрицы, texel bias и PCF получают фактический размер.

MCP: `render.set_shadow_resolution` с `{"resolution":4096}` ставит изменение в
очередь до следующего отрисованного кадра. `debug.get_state.render.lighting`
содержит `shadow_resolution` (фактический) и `shadow_resolution_requested`.
Benchmark JSON содержит `shadow_resolution`.

## Проверки Windows x64

- Debug, Release и ASan: сборки приложения и редактора, 6/6 CTest в каждой.
- Clang-tidy и MSVC `/analyze` + Core Check по восьми затронутым единицам
  трансляции; после корректировок повторно проверены renderer и editor UI.
  В добавленных строках предупреждений нет. Общий код и зависимости сохраняют
  существующие предупреждения; это не утверждение об отсутствии долга во всём
  проекте.
- Debug: три запуска, по два цикла в режимах GI on, GI off и legacy. ASan:
  четыре запуска с теми же режимами, затем дополнительный цикл после финальной
  корректировки границы пересоздания ресурса. Проверены все четыре размера,
  resize окна, present mode, Off/SMAA/FSR, scene/instancing/gpu-saturation,
  отклонение неверных запросов и продолжение цикла суток.
- Vulkan object lifetime/synchronization validation: без ошибок; на каждом
  штатном shutdown — `Live GPU allocations: 0 (0 bytes)`. ASan ошибок не сообщил.
- Возврат к 2048 и повторный выбор 2048: Off/SMAA сохраняют точное совпадение
  пикселей контрольной сетки через 4 пикселя вне HUD. FSR проверен на корректность
  переключения и lifetime, без требования совпадения temporal-кадров.
- Контрольные изображения 1024 и 8192 просмотрены. Ручное управление dropdown
  редактора не автоматизировано; общий renderer проверялся через MCP.
- Шейдеры/SPIR-V не менялись. Проверки других GPU и платформ не проводились.

Команда воспроизведения runtime-проверки (повторить с `off` и `legacy`):

```powershell
scripts/render_validation_windows.ps1 -ExePath build/windows-debug/bin/vulkan_cube.exe -Scenario shadow-resolution -ShadowLighting voxel -Startups 1 -Cycles 2
```

Сценарий проверки всех размеров требует поддержки карты 8192². Логи и PNG:
`build/windows-{debug,asan}/render-validation/shadow-resolution-*`.

## Производительность: 2026-09-12

Baseline — `6bcd388`, сохранённый executable с соответствующими shaders/assets.
Windows Release, RX 6800, драйвер 32.0.21045.5002, Ryzen 7 9700X,
1920×1080, IMMEDIATE, AA off, dynamic lighting, GI off, цикл суток включён,
`--animate-camera`. Три чередующихся прогона каждого варианта: прогрев 5 секунд,
измерение 15 секунд. Сцена, камера и остальные параметры одинаковы.
План питания «Сбалансированная», частоты и температура не фиксировались.
Параллельные сборки, анализаторы и другие тесты renderer во время замеров
не запускались; снимок фоновых процессов сохранён вместе с результатами.

Медианы средних значений прогонов, время в миллисекундах:

| Вариант | FPS (min–max) | 1% low | CPU frame | GPU frame | GPU shadows |
| --- | --- | --- | --- | --- | --- |
| До изменения, 2048 | 2518 (2407–2556) | 1702 | 0.3971 | 0.21926 | 0.00733 |
| После, 2048 | 2506 (2489–2506) | 1722 | 0.3991 | 0.21930 | 0.00733 |
| После, 1024 | 2535 (2505–2591) | 1773 | 0.3945 | 0.21654 | 0.00401 |
| После, 4096 | 2414 (2382–2474) | 1555 | 0.4143 | 0.23490 | 0.02219 |
| После, 8192 | 2064 (2053–2149) | 1166 | 0.4846 | 0.30365 | 0.09017 |

Стандартные 2048: −0.50% FPS, GPU frame +0.00004 ms; разница ниже разброса
прогонов. В одном baseline-прогоне 1% low упал до 786, поэтому улучшение
стабильности FPS по этим данным не заявляется. На CPU большая часть времени
остаётся в present: медиана 0.2870 ms до / 0.2884 ms после. Acquire, fence,
record, submit и полный min/max всех метрик сохранены в `summary.json`.

4096 относительно новых 2048: −3.7% FPS, 8192: −17.6%. Увеличение стоимости
ожидаемо: растёт площадь карты и GPU-время теней. Поэтому стандартный размер
сохранён, а большие размеры доступны как выбор детализации с измеренной ценой.
Это результаты данной сцены с движущейся камерой и кешированием каскадов;
тяжёлые сцены с движущимися casters, GI и другие GPU отдельно не профилировались.
Аппаратные counters и CPU allocation tracing в этой задаче не собирались;
отсутствие новых аллокаций в обычном игровом кадре проверено по изменённому коду.
